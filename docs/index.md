# FORGE documentation

Read the guides in this order. Each guide covers the same four things in turn: **concepts**, **API reference**, **examples** and **platform notes and limits**. Anything that has not been tested is marked as such.

## 1. Start here
1. [README](../README.md): what FORGE is, quick start, repository layout
2. [building.md](building.md): presets, CMake options, cross builds, wine, the Android emulator and qemu
3. [testing.md](testing.md): test kinds, ctest labels and how to run them

## 2. Library layers, bottom up
4. [os.md](os.md): the `forge::os` portability layer, including its 16 extension features
5. [lane.md](lane.md): CPU feature detection and SIMD kernel dispatch
6. [grid.md](grid.md): devices, graphs and parallel primitives
7. [flow.md](flow.md): graph IR, passes, plans, autodiff and RPC devices
8. [pack.md](pack.md): the `.fpk` container, signing, encryption and import
9. [format.md](format.md): the `.fpk` byte layout
10. [mind.md](mind.md): models, sessions, samplers and generation

## 3. Serving and embedding
11. [balance.md](balance.md): load-balancing strategies
12. [serve.md](serve.md): the `forge-serve` HTTP server and its flags
13. [capi.md](capi.md): the stable C ABI (`forge.h`)
14. [bindings.md](bindings.md): Python, Kotlin and Swift bindings

## 4. Reference and project
15. [reference.md](reference.md): API reference generated by `tools/gen_docs.py`
16. [STATUS.md](STATUS.md): what has been tested, and on which platform
17. [RELEASING.md](RELEASING.md): the release procedure
18. [spec/README.md](../spec/README.md): operation specs and code generators

## Compiled examples
The code in `docs/examples/` is built and run by ctest as `doc_example_*`, so the guides cannot drift from the API:
```sh
(cd build/dev && ctest -R doc_example)
```
