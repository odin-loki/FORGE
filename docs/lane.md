# lane: CPU features and kernel dispatch

## Concepts
`forge::lane` detects what the CPU supports and what the OS has enabled (AVX-512 state, AMX permission, SVE vector length, …), then picks **one table of kernel function pointers** for the process. The choice is made once; every later call goes through the table.

The kernels are written once against portable vector types (`vec.hpp`, "Tier P") and algorithms (`algo.hpp`, "Tier A"), and compiled per target in `lane/src/` into the static library `forge_lane_mv`. Raw intrinsic wrappers ("Tier R") are generated from `spec/intrinsics/x86.json`.

Targets per architecture:

| Arch | Targets (best first) |
|------|----------------------|
| x86_64 | `avx512` (needs F+BW+DQ+VL), `avx2` (needs FMA), `scalar` |
| aarch64 | `sve` (fixed-length tables built for 128/256/512/1024-bit VL; the table matching the hardware VL is used), `neon`, `scalar` |
| riscv64 | `rvv` (tables per VLEN 128–1024), `scalar` |
| other | `scalar` |

Matrix tile units are separate (`tile.hpp`): `amx_gemm_bf16`, `amx_gemm_s8` (Intel AMX) and `sme_gemm_f32` (Arm SME). They return `false` when the unit is absent, the OS refuses tile state, or the compiler could not build them, so callers fall back to vector GEMM.

## API (`lane/include/forge/lane/dispatch.hpp`)
- `const cpu_features& detect()`: cached feature flags; `.summary()` gives a one-line description (what `forge info` prints).
- `const kernels& active()`: the table for this process. `FORGE_LANE_TARGET` overrides it if that target is usable.
- `const kernels* by_name(const char*)`: a specific table, or `nullptr` if not built or not usable here. Names: `scalar` everywhere; `avx2`, `avx512` on x86; `neon`, `sve` on aarch64; `rvv` on riscv64.
- `kernels` fields: `target` (name) and function pointers `saxpy`, `dot`, `sum`, `softmax_row`, `rms_norm_row`, `exp`, `log`, `tanh`, `sigmoid`, `silu`, `gelu`, `silu_mul`, `add`, `sub`, `mul`, `gemm_nt`, `gemm_nn`, `math1` / `math2` (extended maths selected by function id), `logsumexp`.
- `math.hpp` holds the vectorised maths library (exp/log families, trig and inverse trig, hyperbolics, erf/erfc, lgamma, pow, hypot, …). Polynomial coefficients for erf/erfc/lgamma are generated by `spec/gen/fit_math.py` into `math_coeffs.hpp`.

## Example
`docs/examples/lane_dispatch.cpp` (ctest `doc_example_lane_dispatch`):

```cpp
std::printf("cpu: %s\n", forge::lane::detect().summary().c_str());
const forge::lane::kernels& k = forge::lane::active();
std::vector<float> x(1000, 1.f), y(1000, 2.f);
k.saxpy(3.f, x.data(), y.data(), x.size());   // y = 3*x + y
float d = k.dot(x.data(), y.data(), x.size()); // 5000
```

## Platform notes and limits
- Link `forge_lane_mv` whenever you use lane (directly or through grid/flow/mind).
- On aarch64, if the hardware SVE length has no matching table (not a power of two, or above 1024 bits), the process lowers its VL with `PR_SVE_SET_VL` at start-up; `FORGE_SVE_KEEP_VL=1` disables that.
- SVE and RVV have run only under qemu-user; AMX has run natively on a Xeon and under Intel SDE; SME only under qemu. See [STATUS.md](STATUS.md).
