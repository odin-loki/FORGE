### Features that are documented as missing
- [ ] **Model families**: Phi-2, Mamba, UNet / DiT denoisers and the Whisper decoder have no template; Phi-3 LongRoPE (128k variants) is refused. No image or audio front end (resize / normalise, log-mel): `forge embed --input` takes preprocessed f32. ([modelfile.md](docs/modelfile.md), [inference.md](docs/inference.md))
- [ ] **Embeddings**: no batch axis in the graph: `session::embed_batch` and `/v1/embeddings` take several inputs per call but run them as a loop with shared setup (done 2026-11-12); the C ABI has `forge_embed_*` and the bindings `embed` (ABI 4, 2026-11-12; Python tested, Kotlin and Swift never compiled); neither the C ABI nor `/v1/embeddings` serves the vision and audio encoders. ([serve.md](docs/serve.md), [capi.md](docs/capi.md))
- [ ] **forge-serve**: one model per process; no HTTP/2, response compression or `HEAD`; rate limits and quotas are per process and in memory; no TLS certificate reload or OCSP stapling; tool calls: Mistral's `[TOOL_CALLS]name[ARGS]{...}` and Llama's `<function=name>` forms are not parsed, arguments are not validated against the schema in `auto` mode; no PEFT-directory converter for `--lora`, no loading or unloading of adapters while serving. ([serve.md](docs/serve.md))
- [ ] **GPU**: the Metal ports of the 2026-11-12 quantised / attention / MoE kernels are a textual MSL translation plus host code that no Metal toolchain has compiled and nothing has executed (the Vulkan GLSL ports ran on lavapipe only); the device kernels for `attention_bias`, `layer_norm`, `gelu`, convolution, pooling and `group_norm` are untimed, untuned direct kernels; `transpose`, `l2_normalize`, `masked_mean`, the resize ops and `batch_norm` still run on the host on every device; no eviction while a CUDA/HIP stream capture is open, and a stale CUDA/HIP capture that holds an evicted encoded weight or a macro-stamped kernel cannot be re-recorded (it throws); `gpu::prims` has no device FFT and no fused-epilogue matmul kernel, and none of the new prims is timed; `pipe:auto` exists but hands activations between stages through host memory (no peer copies, no per-layer byte accounting) and has run on mock drivers only. ([gpu.md](docs/gpu.md), [STATUS.md](docs/STATUS.md))
- [ ] **CPU int8 activations and accuracy**: the int8-activation quantised matmul (x86 default, CUDA / HIP) deviates from the exact quantised result by up to about 1.6 % of the largest output on wide-range inputs; there is no per-model switch other than `FORGE_CPU_INT8=0`. ([gpu.md](docs/gpu.md) "Quantised matmul: exact and int8-activation paths")
- [ ] **C ABI** (ABI 4): no log-probabilities, tool-call helpers, lookup decoding, diffusion / streaming sessions, adapter unload or background batch worker; `forge_aot_precompile` writes plan sidecars only. Device selection ran with `cpu` and a fallback only. ([capi.md](docs/capi.md))
- [ ] **AOT**: device plans are not serialised (CPU only); LoRA adapters are not baked in; sequence lengths are exact (no bucketing); the pass-pipeline version is bumped by hand. ([aot-models.md](docs/aot-models.md))
- [ ] **OS layer**: native Wayland clipboard, portal `OpenFile`, Secret Service; `SO_REUSEPORT` and client TCP fast open on Windows; the per-OS "unsupported" entries of [os-parity.md](docs/os-parity.md). ([os-audit.md](docs/os-audit.md) S11)
- [ ] **RPC**: no OCSP or CRL fetching; device ops have no per-model scope; uploaded weights have no per-rule storage cap, encoded weights are not sent by handle, and activations still travel with every op. **Security**: the known gaps listed in [security.md](docs/security.md#known-gaps).
- [ ] **Scheduler**: `task::sched` is not used by the engine (graph, inference and gpu still use `task::pool`); no performance comparison between the two was made. ([support.md](docs/support.md))
